## 1 Purpose

To provide a single, authoritative reference for the creation and use of lot identifiers across all roles involved in turmeric/ginger powder production: line operators, data encoders, and software developers.  
The guide specifies naming conventions, generation logic, linking rules, validation criteria, and traceability requirements.

---

## 2 Scope

Applies to every lot that is generated or recorded in the IIDA Farms production chain:

|Entity|Role(s) Involved|Typical Interaction|
|---|---|---|
|Raw‑Material Lot|Warehouse Staff, Finance|Record at receipt|
|Ingredient‑Prep Lot|Operators|Issue to cooking|
|Unified Product Lot (Post‑Cooking)|Operators, Encoders, Developers|Create after cooking; propagate downstream|

All documents, forms, and database tables referenced herein must adopt the conventions defined in this guide.

---

## 3 Definitions

|Term|Definition|
|---|---|
|**Raw‑Material Lot (RM‑Lot)**|Unique identifier for a single shipment of raw produce.|
|**Ingredient‑Prep Lot (ING‑Lot)**|Sub‑lot created when raw material is issued for a specific production batch.|
|**Unified Product Lot (LOT‑Lot)**|Single lot that represents the finished product after cooking; used for all subsequent steps.|
|**Product Code**|Three‑ to five‑letter code derived from the SKU’s `product_code` field (e.g., `TGLM`).|
|**Sequence**|Zero‑padded four‑digit counter that restarts each day for every product code.|
|**Date Stamp**|Production date in `YYYYMMDD` format (e.g., 20240610).|
|**SKU**|Stock‑Keeping Unit; contains product code, pack type, and size.|
|**PIC**|Person In Charge – employee ID + name.|

## 4 Lot‑ID Naming Conventions

|Entity|Table / Field|Format|Example|
|---|---|---|---|
|**Raw‑Material Lot**|`RAW_MATERIAL.raw_mat_lot`|`RM‑<PROD-CODE>‑YYYYMMDD‑####`|`RM‑GIN‑20240610‑0001`|
|**Ingredient‑Prep Lot**|`INGREDIENT_PREP.ingredient_lot`|`ING‑<RAW-MAT-LOT>‑YYYYMMDD‑####`|`ING‑RM‑GIN‑20240610‑0001‑001`|
|**Unified Product Lot**|`LOT.lot_number` (or `COOKING_LOT.cooking_lot_id`)|`LOT‑<PROD-CODE>‑YYYYMMDD‑####`|`LOT‑TGLM‑20240610‑0001`|

**Rules**

1. All identifiers are uppercase and hyphen‑separated.
2. `<PROD-CODE>` is the product code from the selected SKU (see Appendix A).
3. `<YYYYMMDD>` is the calendar date of lot creation (raw receipt, prep start, or cooking finish).
4. `####` is a zero‑padded 4‑digit sequence that **resets to 0001 each day per product code**.

## 5 Lot Creation Workflow

### 5.1 Raw‑Material Lot (Warehouse)

1. **Receive** raw material and record procurement details.
2. Generate the RM‑Lot using the format above (auto‑generated by the receiving system).
3. Store the RM‑Lot in `RAW_MATERIAL.raw_mat_lot`.

### 5.2 Ingredient‑Prep Lot (Operator)

1. **Select** the RM‑Lot to issue.
2. Record the issuance in `INGREDIENT_PREP` and generate an ING‑Lot using the format above.
3. Note the **PIC** and endorsement datetime.

### 5.3 Unified Product Lot (Post‑Cooking) – _Key for all roles_

|Role|Responsibility|
|---|---|
|**Line Operator**|After cooking completes, input the list of ING‑Lots used and request a new LOT‑Lot.|
|**Encoder**|Validate the incoming LOT‑Lot, verify linkage to ING‑Lots, and enter into the production database.|
|**Developer**|Implement logic that: <br> • Retrieves the product code from the selected SKU. <br> • Reads the current date (`YYYYMMDD`). <br> • Queries the maximum existing sequence for that product code and date. <br> • Increments it, zero‑pads to 4 digits, and concatenates to form the new LOT‑Lot. <br> • Ensures uniqueness via a database constraint or trigger.|

**Step‑by‑step (Operator)**

1. **Confirm SKU** – operator selects the finished product SKU on the cooking completion screen.
2. **Derive Product Code** – system pulls `product_code` from the SKU table (e.g., `TGLM`).
3. **Generate LOT‑Lot** – system auto‑creates `LOT‑TGLM‑20240610‑0001` (first lot of the day).
4. **Record** – operator verifies and confirms the ID on the cooking completion form.

## 6 Sequence Generation Rules (Developer Reference)

1. **Query**: `SELECT MAX(SUBSTRING(lot_number, 9, 4)) FROM LOT WHERE lot_number LIKE 'LOT-<PROD-CODE>-YYYYMMDD-%'`.
2. **Increment**: If `NULL`, start at 1; else add 1.
3. **Zero‑Pad**: Convert to string, pad left with zeros to length 4.
4. **Concatenate**: `LOT-<PROD-CODE>-YYYYMMDD-<SEQ>`.

_Note: The system must lock the sequence table or use an atomic increment to avoid race conditions._

## 7 Linking and Traceability

|Level|Relationship|
|---|---|
|RM‑Lot → ING‑Lot|One-to-many (one raw lot can produce many prep lots).|
|ING‑Lot → LOT‑Lot|Many-to-one (multiple prep lots combine into one cooking lot).|
|LOT‑Lot → Downstream Steps|One-to-many (each subsequent process step references the unified lot).|

All forms and database tables must include foreign‑key relationships that enforce these links.

---

## 8 Validation & Error Handling

|Validation|Trigger|Action|
|---|---|---|
|**Format**|On entry (UI & API)|Reject if not matching regex `^LOT-[A-Z]{3,5}-\d{8}-\d{4}$` (and similar for RM‑ and ING‑lots).|
|**Uniqueness**|Database constraint|Fail transaction; notify operator/encoder.|
|**Sequence Gap**|Daily reset logic|Allow gaps (e.g., if lot 0002 is missing, the next will be 0003).|
|**Missing Link**|During data import|Flag records where `ING‑Lot` or `RM‑Lot` cannot be found; require manual review.|
